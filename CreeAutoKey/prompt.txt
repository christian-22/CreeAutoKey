# Build a Simple Windows Input Automation App (.NET 10 + C# 14)

You are an expert Windows/.NET developer. Generate a complete, minimal-but-robust **Windows-only** desktop application using **.NET 10** and **C# 14** that automates keyboard/mouse input via Win32 APIs.

## Goal
Create a small app that can:
1. **Hold** selected keyboard keys and/or mouse buttons down indefinitely.
2. **Repeat-click** selected keyboard keys and/or mouse buttons at a user-defined interval measured in **seconds**.
3. Use a user-configurable **global toggle hotkey** to turn the automation on/off even when the app is not focused.
4. Include **hard emergency stops**: `Esc` and `Ctrl+Alt+End` (non-configurable) that immediately stop automation and **guarantee release** of all held inputs.

⚠️ Important constraint: **Do not attempt to capture Ctrl+Alt+Delete**. It cannot be intercepted by user-mode apps. You may display it as “system bailout,” but do not rely on it for stop/release logic.

## UX Requirements
- Keep it **incredibly simple**.
- Always-on-top **tiny status window** (not the taskbar/tray) that shows:
  - State: `OFF`, `3`, `2`, `1`, `ON`
  - Toggle hotkey
  - Hard stops: `Esc`, `Ctrl+Alt+End`
- A **3-2-1 countdown** occurs when enabling automation (toggle ON). Countdown should be cancelable by toggle OFF or emergency stop.
- A **Developer Mode** window for testing:
  - “Test panel” showing current configuration and current held inputs
  - Log window streaming events (bounded ring buffer is fine)
- I do **not** want press duration for the “hold” feature. Held inputs stay down until stopped.

## Platform/Tech Requirements
- Windows-only desktop app.
- Use **WPF** (preferred for speed of implementation) on .NET 10.
- Global hotkeys must work while app is unfocused:
  - Use Win32 **RegisterHotKey** and process **WM_HOTKEY**.
- Input injection must be done using Win32 **SendInput** (P/Invoke):
  - Support keyboard key DOWN/UP
  - Support mouse buttons DOWN/UP (left/right/middle at minimum)
- Use `async`/`await` for countdown and repeat loop scheduling.
- Clean separation of concerns but avoid overengineering. Keep project structure small.

## Functional Requirements (Details)
### Configurable
- Toggle hotkey: allow user to set a combo like `Ctrl+Shift+T` or a single key like `]`.
- Hold bindings: user can pick multiple keyboard keys and/or mouse buttons to hold.
- Repeat bindings: user can pick multiple keyboard keys and/or mouse buttons to click.
- Repeat interval: numeric seconds (allow decimals like `0.1`), must be validated and clamped (e.g., min 0.01s).

### Non-configurable safety
- Emergency stop: `Esc`
- Emergency stop: `Ctrl+Alt+End`
- Emergency stops must work globally and immediately.

### Guarantees
- On ANY stop path, always release:
  - All keys/buttons that the app has held down
  - All mouse buttons that the app has pressed down
- Stop paths include:
  - Toggle OFF
  - Emergency stop
  - App closing
  - Unhandled exception paths (best effort): DispatcherUnhandledException, TaskScheduler.UnobservedTaskException, ProcessExit
  - Session ending/locking events (best effort)

### Behavior
- Toggle ON: show countdown `3,2,1,ON`. Only apply holds after countdown completes.
- Running:
  - Held bindings are pressed DOWN and remain DOWN.
  - Repeat bindings are clicked at the configured interval:
    - For key click: DOWN then UP
    - For mouse click: DOWN then UP
- Toggle OFF or emergency stop:
  - Immediately cancel countdown/repeat loops
  - Release all held inputs
  - Set state to OFF

## Data Model
Define a simple representation for bindings, e.g.:
- `InputBinding` with kind `{ KeyboardKey | MouseButton }`
- Keyboard: virtual key code (VK)
- Mouse: enum for Left/Right/Middle

Track which inputs are currently held by the app so releases are deterministic.

## Architecture (Recommended)
Implement these components:
1. `AutomationEngine`
   - State machine: Idle, Countdown, Running
   - Owns CancellationTokenSource
   - Methods: `StartAsync()`, `Stop(reason)`, `EmergencyStop(reason)`
2. `HotkeyService`
   - Registers: Toggle hotkey, Esc, Ctrl+Alt+End
   - Raises events on hotkey pressed
3. `SendInputInjector` (IInputInjector)
   - P/Invoke SendInput for keyboard/mouse
   - Helpers: KeyDown/KeyUp, MouseDown/MouseUp
4. `ConfigStore`
   - Persist config to JSON in user AppData (simple)
5. `Logger`
   - In-memory ring buffer for Dev Mode UI

## UI Screens
1. **MiniStatusWindow** (AlwaysOnTop)
   - big state text

2. **MainWindow**
   - Toggle hotkey picker
   - Hold list: add/remove keyboard key or mouse button
   - Repeat list: add/remove keyboard key or mouse button
   - Interval seconds input
   - Toggle ON/OFF button (optional; global hotkey is primary)
   - Enable Developer Mode checkbox/button
3. **DeveloperModeWindow**
   - Current state + held inputs
   - Recent hotkey events
   - Log stream
